## 9. Monetisation and Entitlement Model

White Label Branding should be sold as a paid add-on module.

### 9.1 Locked State

If the organisation has not purchased or activated the Branding add-on:

- Branding entry point remains visible but locked.
- User sees what is included in the module.
- User sees pricing or plan eligibility where available.
- CTA should be `Unlock White Label Branding` or `Buy Branding`.
- CTA redirects to Subscription / Add-ons purchase flow.

### 9.2 Post-purchase Unlock

After successful purchase:

- Branding module becomes accessible for the organisation.
- Admin/Owner with required permissions can create or edit the branding configuration.
- If mobile app branding is included, App Build Tracking becomes available.
- If only Web branding is purchased, mobile app build status remains hidden or upsell-gated.

### 9.3 Package Types

The purchase flow includes a decision point where customers choose Web, App or Both.

| Package | Description | Initial Recommendation |
| --- | --- | --- |
| Web Branding | Logo, colours, legal links, domain and web app identity. | Phase 1 |
| Android App Branding | Branded Android app build, delivery tracking and approval flow. | Phase 1 / 2 depending on engineering readiness |
| iOS App Branding | Branded iOS app build; lower demand and higher operational dependency. | Phase 2 |
| Web + App Bundle | Combined web and mobile branding. | Phase 2 |
