## 2. How to Use This Guide

This package is a self-contained implementation guide for the White Label Branding feature. It documents the approved Admin Whitelabel Manager, the customer-side management direction, runtime theme behavior, domain controls, authentication options, mobile delivery, permissions, validation, analytics, and acceptance criteria.

Screenshots are embedded beside the workflows they explain. Every image uses a relative `assets/...` path so the package can be imported into GitBook without external design links.

The screenshots use demonstration organisations, brands, domains, credentials, dates, URLs, colours, and QR codes. Production values must always come from the selected organisation, active entitlement, and authenticated user's permissions.

Requirement language follows these rules:

| Term | Meaning |
| --- | --- |
| Must | Required for release acceptance. |
| Should | Recommended unless an engineering or product constraint prevents it. |
| May | Optional behavior or future-compatible extension. |
| Runtime mobile theme | Remotely supplied colours and supported brand assets applied without a new app build. |
| Branded mobile build | Store or package identity that requires the app-build and release workflow. |
