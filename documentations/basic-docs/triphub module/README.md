## Overview

TripHub is Bolt's configurable operations-planning and trip-execution module. It lets an organisation define operational service locations, group those locations into haltpoints, build routes, create executable trips, assign vehicles and workforce, monitor execution, and review performance from one unified workspace.

TripHub supports multiple operating models, including waste management, school transport, employee transportation, logistics and delivery, inspection or survey operations, and field-service operations. Bolt Web covers Territories, Targets, Haltpoints, Routes, Trips, Map view, Path Replay, adhoc handling, route creation, trip creation, and operational monitoring. Bolt Workforce Mobile adds driver-facing execution through My Trips, trip cards, start-trip checks, route timelines, target service states, proof capture, adhoc requests, hold/completion actions, SOS, breakdown, calling, and forms. Attendance, parent visibility, HRMS integrations, and advanced route-type rules remain connected capabilities that must be enabled only where the organisation requires them.

TripHub should answer six core operational questions:

- **What locations, customers, bins, students, assets or service points need to be served?**
- **How are these targets grouped into haltpoints and territories?**
- **Which routes should be created, scheduled or optimised?**
- **Which trips are assigned, in progress, blocked, completed or missed?**
- **Where is the trip or route execution happening on the map?**
- **What operational actions are required when there is an adhoc request, breakdown, missed target, route deviation or workforce exception?**
